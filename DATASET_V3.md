# `train_v3`: очистка и воспроизводимость

`data/train_v3.jsonl` — очищенная версия обучающей выборки, построенная из
`data/train_v2.jsonl` скриптом [`scripts/build_train_v3.py`](scripts/build_train_v3.py).
Исходные `train.jsonl` и `train_v2.jsonl` не изменяются.

## Что исправляется

### 1. Дубликаты с противоречивой разметкой

Записи группируются по полному совпадению поля `text`. Для каждой группы
выбирается наиболее поддержанная сигнатура сущностей. При равенстве голосов
приоритет получает запись, которая уже была в исходном `data/train.jsonl`, затем
выбор становится детерминированным по `hash`. Остальные копии удаляются.

В исходном `train_v2` было 44 598 записей. Найдены 2 группы одинаковых текстов с
разными аннотациями; удалены 2 дублирующие записи. В `train_v3` остаётся 44 596
записей, по одной записи на уникальный текст.

### 2. Внешние пробелы и пунктуация в span

Перед дедупликацией у каждой сущности удаляются внешние пробелы и разделители,
которые по [`LABELING_GUIDE.md`](LABELING_GUIDE.md) не должны входить в
упоминание: кавычки, скобки, `#`, `@` и конечная пунктуация. Внутренняя
пунктуация, апострофы, дефисы и точки внутри названия сохраняются. После
обрезки пустые сущности удаляются, а ставшие дубликатами spans объединяются.

В результате изменены 2 346 spans: 48 имели начальный внешний разделитель и
2 315 — конечный. После очистки осталось 247 262 сущности.

Это механическая нормализация по формальным правилам. Аббревиатуры и бренды,
оканчивающиеся точкой, требуют отдельного ручного аудита; полный список
изменений и конфликтов хранится в `data/train_v3_audit.json`.

### 3. Поверхностно неоднозначные названия

Одинаковая строка с разными классами не всегда является ошибкой: руководство
определяет класс по роли в контексте. Например, `Andijon` может быть городом
(`GEO`) или организацией/клубом (`ORG`). Поэтому `train_v3` не заменяет все
редкие метки на самый частый класс и не уничтожает контекстный сигнал.

После очистки для каждой нормализованной поверхности сохраняется распределение
классов в `data/train_v3_audit.json` (`ambiguous_surfaces`). Это позволяет
отдельно провести ручной аудит действительно ошибочных случаев, не смешивая их
с легитимной полисемией. Противоречия в одинаковом полном тексте устраняются
правилом дедупликации выше.

## Воспроизведение

Из корня репозитория:

```bash
python scripts/build_train_v3.py \
  --train data/train.jsonl \
  --train-v2 data/train_v2.jsonl \
  --output data/train_v3.jsonl \
  --audit data/train_v3_audit.json
```

Скрипт детерминирован: он не использует случайность, сеть или внешние модели.
Проверка формата и координат:

```bash
python - <<'PY'
from pathlib import Path
from baseline.common import read_records
rows = read_records(Path("data/train_v3.jsonl"), require_entities=True)
print(len(rows), sum(len(row["entities"]) for row in rows))
PY
```

Ожидаемый результат текущей версии: `44 596` записей и `247 262` сущности.

## Ограничения и следующий аудит

- Скрипт не пытается угадывать контекстную роль неоднозначной поверхности.
- Автоматическая обрезка конечной точки может быть спорной для сокращений и
  брендов; такие изменения перечислены в audit-файле и должны быть выборочно
  просмотрены.
- `train_v3` устраняет дубли и span-шум, но не меняет исходный перекос
  `train_v2` по алфавиту и классам. Балансировку следует делать в sampler или
  отдельным явно документированным шагом.
